## The brief

CuanCerdas was built for the **Paylabs × Alibaba Cloud Mini Hackathon 2026** — a
build-and-pitch competition judged on a live demo, run on Alibaba Cloud infrastructure
with Paylabs (a payment gateway) as the data partner. I led a four-person team — Team Jo —
through the build, and we placed **2nd**.

## The idea

We bet on **financial literacy for Indonesian MSMEs (UMKM)**. The gap is real and large:
**87% of UMKM** don't do basic financial management — budgeting, recording, reporting,
controlling — and **over half** of owners finished only primary school, which caps
financial literacy and strategic planning. Yet UMKM are **60.5% of Indonesia's GDP** and
**96.9% of national employment**, and 2 in 5 have never touched AI. They sit on a goldmine
of transaction data (everything they run through Paylabs) but have neither the time nor the
training to read it, and generic chatbots don't help because the advice isn't grounded in
the business's actual numbers.

So we built a **finance copilot**: an AI agent that turns a merchant's Paylabs transactions
into a clean, structured financial report — and a chatbot, **JO**, that explains that report
in plain language and advises on it. The framing we pitched on: *"we don't just tell UMKM how
much money they make — we teach them how to manage and grow it through AI."*

## My role

I led the team as **Team Lead** and worked **full-stack** across the build — the agent
design and the MCP grounding layer, the Fastify backend and report pipeline, and the live

## Building it

The system is two AI behaviours over one shared, grounded data layer:

- **Report-generation agent** — turns a date range of transactions into a structured
  report: revenue, COGS, OPEX, gross/net profit, net margin, ending cash, category and
  channel breakdowns, and a previous-period comparison. Generation is asynchronous and
  callback-based: the frontend kicks off a job, the agent does its analysis, writes results
  to a staging row, and the backend persists the finished report into normalized tables and
  renders the dashboard summary, charts, insights, and a PDF export.
- **Advisor chatbot (JO)** — a streaming financial advisor. The browser holds a WebSocket to
  the backend, which relays a token stream from the agent (NDJSON over HTTP). JO is
  merchant-scoped and report-anchored: it lists the merchant's reports, pulls only the
  relevant one, loads recent chat context and a transaction summary, and answers from there.
  Users can pick the advisor model per chat from a live allowlist.

The piece I'm proudest of is the **grounding layer**. The agent never runs free-form SQL —
it talks to the database through an **MCP server** that exposes a fixed catalogue of typed
tools (`get_report_metrics`, `list_available_reports`, `get_advisor_report`, …), so every
number JO cites is computed deterministically, not hallucinated. `merchantId` is the hard
data-isolation boundary, so a merchant can only ever see its own books. That discipline shows
up in JO's behaviour: when a user asked it to "set a 1–5% inventory-efficiency target for the
next two weeks," JO pushed back — the transaction schema is category-level, there's no
SKU/turnover data to support a target like that — and explained *why*, instead of inventing a
confident-sounding number.

The stack: a **Fastify + TypeScript** backend (Prisma, Zod, PDFKit, WebSocket relay, JWT
auth), a **FastAPI** agent service, the **MCP** tool server, and **PostgreSQL** — all running
on **Alibaba Cloud** (ECS for compute, OSS for storage), with the agent powered by **Qwen**.

## Pitch day

We pitched the business case as hard as the demo: a **freemium** model where basic reporting
and general literacy education are free for every Paylabs merchant, with the deep AI mentor
and predictive analysis behind a monthly subscription — turning Paylabs from a payment
*utility* into an *ecosystem* for UMKM.

## Outcome & takeaways

We finished **2nd place** with a working technical MVP — not just a concept deck: real async
report generation, real streaming advisor responses, structured DB-backed persistence, and
merchant-scoped, deterministic data access through the MCP tool layer.
